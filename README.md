<h1>osTicket - Ticket Lifecycle: Intake Through Resolution</h1>
In this project I will demonstrate the lifecycle and the process of working a ticket within osTicket.<br />



<h2>Environments and Technologies Used</h2>

- Microsoft Azure (Virtual Machines/Compute)
- Remote Desktop
- Internet Information Services (IIS)

<h2>Operating Systems Used </h2>

- Windows 10</b> (21H2)

<h2>Ticket Lifecycle Stages</h2>

- Creating ticket as end user 
- Assigning ticket properties as Agent 
- Working the Issue
- Resolution

Step 2: Assigning ticket properties as an Help Desk Agent: In this step I demonstrate the process of being a help desk agent who recieves this support ticket and assigns the correct properties for this ticket to get to the right team. The first step is to assign the propery SLA properity for this ticket. This ticket is an urgent issue because customers are unable to access their online bank accounts, which means it will recieve the highest level SLA. Tickets that receive this level of urgency are usually business critical and need to be resolved as quickly as possible. After assigning the proper SLA for this ticket that agent will transfer the ticket to the proper department. This ticket is in refrence to an issue with the online banking system so it will be transfered to one of the agents on the online banking team.

<p>Step 3: Working the ticket: In this step I demonstrate the process of working this support ticket as an agent on the online banking team. The agent working the ticket looks into the issue to see if they can find the source of the problem. Once they have identified what they belice the problem is they report to the user who submitted the ticket. After reporting the issue to the user the agent goes into the back end of the online system to complete the necessary steps to resolve the issue. In this example the agent goes into the online banking system and deactivates the recent system updates that are causing users to be unable to access their accounts. Once the updates have been deactivted the agent reports the issue to the vendor from which the updates came from so that the issue can be fixed. The agent then updates the user who submitted the ticket by letting them know what steps they took to resolve the issue and that the online banking system should be up and running.

Step 4: Ticket Resoultion: Once their are no further actions steps the agent will go into the osTicket System and mark this ticket as resolved. This clears the ticket from their dashboard and they can move onto the next support ticket in the que.
